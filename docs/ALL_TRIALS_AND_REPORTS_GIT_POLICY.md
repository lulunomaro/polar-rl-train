# 所有试错与报告的Git记录政策

2026-11-03人类要求清理重复目录和文件膨胀。保留试错历史不要求重复复制或永久展开每个实验目录：相同SHA文件引用原Git路径即可；共用源码、资产、模型按版本和SHA引用；旧阶段可以去重压缩归档并删除校验通过的展开副本。当前目录只保留实际工作需要的依赖和结果。禁止以记录政策为由继续每轮复制整套源码或制造无必要的派生脚本。

人类原话（2026-10-09）：“记住我们的所有试错，所有报告都得git来记录”。这是本项目持续有效的记录要求。项目规则、后续AI交接与mod4-10巡检都应引用本文件，不只依赖聊天记忆。

## 必须保留的内容

每次实际试错都有独立ID，保存问题、当时源代码/配置/来源检查点SHA、实际协议/seed/参数/时钟/环境数、实际运行结果、失败原因、改动、验收和未完成项。成功、失败、无效探针、部署前拒绝、回退、observer/reader/schema错误都保留；原始状态和后续修复并列，不覆盖失败或把未运行写pass。

所有落盘报告均进入Git：Markdown/JSON报告、评测摘要、失败/拒绝/修复记录、完整参数与准入审查、交接/工作单、同步pending/成功回执、Git前一阶段记录回执、最终验证报告以及保存的巡检报告。归档前没有报告的健康巡检可以静默；一旦创建了报告，就必须纳入本阶段或后续补充提交，不能因“仅metadata/读者/健康保存”而永久遗漏。新的同步/验证报告生成在阶段提交之后，也要补入Git。

同一阶段可一次归档多份报告与试错，但每次真实尝试仍有独立ID和实际状态。已有字节SHA相同的报告可在索引中引用既有Git路径，不必复制同一内容。报告索引列出原路径、字节数、原SHA、归档路径/归档SHA、完整/脱敏/大型索引状态；不能把只存在本地、待推送或仅有文件名说成已经入Git。动态文件按真实采集时刻冻结，后续变化追加版本。

## 提交与验证

新真实阶段/实验/修复/拒绝/部署用 `archive_tools/record_experiment.py` 生成唯一annotated trial。保持旧commit/tag/raw/成本；核验远端main、tag对象与peeled commit。若commit成功但push失败，继续推已有objects，不重复record或重新造标签。新报告可随对应阶段或一个明确的补充归档提交，避免给每次健康checkpoint单独造实验标签。

阶段结束或向人类报告完成前检查报告清单与Git是否对应。尚未提交/同步的报告必须如实标pending，并积极补齐；不得为补档重跑已有once或GPU评测。Git提交后的远端验证可以作为工具输出保存于本任务，避免产生“每个新验证文件又需要另一次验证文件”的无限循环；若另存成正式报告，该文件同样遵守补入Git要求。

## 大型原件、凭据与历史缺口

凭据、密钥、token不输出、不入Git。确需脱敏时保留原始与归档SHA、脱敏数量及原因，不输出被替换的值。模型权重、大型raw/NPZ/USD/ZIP/视频等原件保留在实际来源，只把真实路径、大小、已有/实算SHA与关联报告索引进Git；未取得的SHA标未知，不伪造。文字报告不能因为底层权重大而一并不提交。

过去已删除、未落盘或缺源码的试错不能凭空重建；索引如实列缺口和证据等级。不要声称整个电脑/所有AI历史已完整恢复。新补档使用真实当前提交时间，原尝试日期另列，不能回填伪造Git历史。

本政策不改已批准主计划SHA，不增加预算，不hotpatch/kill/双开训练，不复制或清canonical，不重跑旧stage/launch/record/sync/恢复once，不新增S8批准。Git归档不是训练依赖；主机继续在自身完整保存、安全接管与实际账段边界运行。
