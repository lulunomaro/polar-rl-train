# 地形子专家与冻结旧能力：可行性审查草案

人类最新提问：“e1地形专家细分为过起伏专家，上台阶专家，等等好多适应不同的专家不就好了？这样也不会退化这种情况，你觉得可行吗？我们用moe专家不就是为了解决这种情况吗”。此处记录设计评审意见，尚未批准或部署新的专家职责、K值、路由器或学习执行器。

结论：可行，而且独立权重保护正是本项目采用专家路线的目的。当前只是 E0 冻结、E1 独立训练，学习门控尚未实现/训练；E1 内部仍用同一 actor 顺序学不同课程，所以专家内部仍会遗忘。原计划划分过粗，不能把“计划叫 MoE”误当成已经具备细分专家隔离。也不应无限要求地形专家重新具备平地专家的全部能力。

本轮实际130完整配对：source365 的35mm前完整路线24/27→25/27、倒27/27、ordinary0，但负4π7/8→1/8、world63/64→59/64/maxcross.074235078m/s。该事实是 E1 内部旧能力变化，不证明冻结 E0 权重变化或未训练的门控失效。保留所有原false/raw/成本及两个有效未完成前缀。source365的后续盲续训拒绝决定保持；source364 SHA3c97作为已审比较与修复来源，不能凭此草案自动注册成熟专家或改选source365。

## 建议的最小分工

| 分支 | 职责与课程 | 保护方式与当前证据 |
|---|---|---|
| E0 平地 | 站立、正反直线、左右原地旋转；已验证的低速world范围 | 原冻结来源和完整D7/D9 registry须实读重核；不让地形学习更新其actor/std/统计/状态 |
| E1-Wave 起伏通行 | 10→20→35→50mm，再按RM003验证真实70mm完整十波与两轮前后支撑 | 目前35mm source364/365均有完整审查但并非全路线毕业；独立保存，不能让跨坎课程覆盖这个分支 |
| E1-Curb 跨坎 | 竖直坎20→35→50mm及150mm条带；再按002外缘真实44.241/92–94/149.929/200.069mm分别准入 | 新合同与行为尚待实施；外缘窄条坎和阶梯不是同一几何，不能把上岛过程叫统一5cm台阶 |
| E1-Slope 坡面 | 当地5→8→10度；世界角与当地角分列，上下行、倒退与停起 | 沿原RM003推进，独立学习；未核11/15/23/43度路线不能借分专家自动准入 |
| E1-Stair 真正台阶（后续候选） | 实际踏面/踢面与完整进出路线，须先核CAD和原授权范围 | 不据名字部署未核台阶；若改变现有职责/范围，写清新版本再执行 |

先从已有起伏证据与一个确有冲突的新地形分支建立最小原型，再根据匹配对照决定是否增加分支；不为每个高度、方向、seed或名字复制网络。上/下行和前/后退是否再拆，应由方向冲突的实际结果决定。

## 怎样真正保护旧能力

每个分支拥有独立actor/critic/optimizer/std、完整D0–D7、RNG/延迟队列/terrain/命令状态与自己的完整保存receipt。只更新正在训练的分支；成熟分支冻结，训练前后逐组SHA/梯度/可变统计验证隔离。新分支可从明确完整已审来源暖启动，但不能共享会被新PPO写入的参数或归一化状态。不能同一SHA换多个名字就算多个专家。

门控阶段冻结合格专家，按原计划hard top-1每个控制步选一个专家的完整六维动作；不默认动作平均、参数融合或新增层级路由。现有35维部署反馈与正常任务命令可能无法在接触前区分起伏、坡面、台阶，必须实际核验可观测性；不得把env_id、地形assignment/真值、未来接触喂actor/gate。若需要新传感或接口，单独提出迁移与审批范围。无证据专家保持禁用。

先比较固定专家+规则选择，再同专家+学习门控；专门审平地↔起伏↔坡面/坎的过渡、上一步实际动作语义、动作与力矩跳变、防抖、每次完整路线、两signed方向与有效失败前缀。冻结旧专家只保证其权重不会被新任务覆盖，不保证错误路由、切换或未覆盖地形能成功。单个专家内部仍可能因新难度、方向或DR更新退化，需要自己的有界配对评审。

“过起伏时旋转移动”需要该状态下的合格专家，不能默认由平地旋转专家与起伏直行专家自动拼出。原S7地形旋转净空、逐档转速与排除项保持；S8危险reset仍按后续具体批准。

## 对当前修复队列的影响

V3新增旧平地pure采样CPU组件保持未部署对照候选，其20000 CPU检查不是物理或抗遗忘证明。先核实E0/E1注册与冻结隔离、区分地形本身的缺口和整机旧技能缺口，再决定是否值得让E1补平地pure；不能自动把E1平地4π作为所有地形课程的唯一否决项，也不能借MoE放松真实数据/硬件/闭链/路线验收。原130拒绝、source364选择与所有false保持；不重跑旧once，不自动第三900s或50mm。

本草案提出更细的专家职责。原主计划第14节要求这类改动用明确新版本审阅；当前人类是在询问可行性，不能伪填PLAN_APPROVAL或直接开新K路由训练。可先完成来源、接口、隔离与任务边界的CPU准备，整理最小对照、成本和退出条件。主SHA812a4bedd04834a98a7c9391609d0056b47c47398e0ecdda9c61e61c6466d05b、原五族配方、时钟/reward/LR/KEEPSTD1/hardware、唯一828000s预算、其他专家/gate与修复规划保护不变，无新训练或预算事务。

依据：已批准主计划第3/7/8/11/14节、RM003/002/001及本轮完整130数据。外部主文[MELA](https://arxiv.org/abs/2012.05810)说明分开预训练专家再学习门控的研究方向，但该研究运行时融合网络，不能拿来证明本项目hard top-1、永久冻结或抗遗忘已通过。华南虎实际V14仍是ActorCritic/PPO，其多模式采样和不同公开技能分支可借鉴，CLI的MoE入口不构成已验证永久抗遗忘证据。
