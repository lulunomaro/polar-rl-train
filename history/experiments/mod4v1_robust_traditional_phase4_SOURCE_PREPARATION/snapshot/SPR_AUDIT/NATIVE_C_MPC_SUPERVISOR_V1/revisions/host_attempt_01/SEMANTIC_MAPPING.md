# Source v2 mapping and explicit new native contracts

The frozen parent [supervisor_v2.py](<../../C_ACTIVE_MPC_SUPERVISOR_V1/supervisor_v2.py>) remains unchanged. The new [C API](<nm1_supervisor.h>) is not an old IO ABI.

1. C3 float inputs are copied/provided by caller, with explicit valid/enabled bits and equal base/drive packet epochs. No estimator, P25, online driver or physical binding is added. Caller vouches for C3 provenance/age; epoch equality does not measure CAN.
2. Independent GUARDED float6 is promoted exactly to double and saved before solving. Invalid base zeros output and last_u, leaves warm/accepted alone, and does not clock/solve/count fallback, matching source. Typed malformed input/context/alias/config adds explicit fail-closed invalid/API outcomes instead of Python exceptions. Alias output is unusable and must be inhibited.
3. All valid-base paths compute the same signed wheel envelopes, yaw differential from MATH_TAU, intersection and inward float32 nextafter bounds. Guard thresholds and speed preclip are unchanged. Domain/disabled/latch takes precedence over no-box. Overspeed brake-only quadrants are retained.
4. Compile-time H32 is bit-identical to existing actual H15. The binary64 compressed Mstate/Mref/Mv changes addition/multiplication order versus NumPy BLAS; numerical rather than bit-exact gradient/torque parity is preregistered. No regularization or profile tuning. Source last_u (including fallback common) is the lag ninth state. Warm is shifted before the single real ab3_solve call; no restarts or fake-solver path.
5. Caller certificate rechecks valid/status/n, z feasibility, finite conservative upper in [0,float32(.002)] and independently double projected KKT <= the unchanged tolerance. Fixed bounds have projected KKT0. Finite cost/unused result slots are not control inputs. Bad-certificate helper tests are separate from real integration, not callback corruption.
6. Namespace reasons correspond to source disabled/latch/domain/no-headroom/nonfinite-gradient/pre/post/mux/final deadlines/nonconverged/certificate/point-guard/clock. Expected invalid ASQP statuses do not commit or latch by themselves, matching v2; clock and certificate faults latch. Explicit init resets; no auto-restart. Counter overflow saturates rather than wrapping (new typed extension).
7. External cycle_start_ns is u64 ns and may precede C3. The callback returns availability plus monotonic ns; all actual raw samples are checked >= cycle_start and >= the previous raw sample. Callbacks receive read-only phase/unit diagnostics, must not mutate/reenter/actuate, and their opaque storage must be disjoint from core objects.
8. The PRE_QP raw sample determines remaining floor microseconds. The ASQP adapter returns that already-observed PRE_QP microsecond origin for its START seed (not a new START hardware measurement), while still sampling/checking actual raw ns at START. Later kernel polls return actual raw ns/1000. This deliberately includes entry overhead in the remaining interval; combined flooring may abort less than 2us early, never enlarges the complete deadline. It avoids resetting the whole-cycle budget at a delayed START. Returned qp_stats.start_us is this anchored origin. Absolute caller enforcement and the final raw-ns check remain external to the sealed kernel.
9. An unavailable/backward raw clock is separately latched in the native supervisor. The adapter uses explicitly nonphysical UINT64_MAX/0 poison values solely to make the unchanged cooperative kernel terminate even on a START failure at zero; kernel timing stats on such a flagged path are not measured time. Faulted clock always discards candidate and reports clock_valid0. No unavailable sample is called a successful real timestamp.
10. Final raw poll happens for every valid base path, including disabled/domain/nonconverged. Warm, accepted sequence and count are committed only afterwards. On failure/deadline, all six returned torques revert to independent GUARDED, accepted_z stays zero, warm stays unchanged, last_u becomes fallback common. The kernel's private storage/result is diagnostic scratch, not an accepted command.
11. output.valid means valid C3 base/selected mathematical fallback or MPC tuple, NOT on-time driver eligibility. clock_valid/deadline_missed/phase are explicit. Work after final poll, return/copy, caller scheduling, actual driver envelope/BSP and C3 final enqueue are not covered; actuation qualification is absent.

No SDK, stdio parser/worker, physics, GPU, Git, agent, parent-goal or old-package modification is part of this functionality. New M4/M7 object facts and new host interfaces are separate receipts, not runtime/WCET certification.
