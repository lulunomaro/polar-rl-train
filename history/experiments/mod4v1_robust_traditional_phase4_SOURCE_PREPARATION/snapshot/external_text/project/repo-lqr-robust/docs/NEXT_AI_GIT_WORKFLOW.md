# 接管 AI 的 Git 记录要求

仓库：https://github.com/lulunomaro/polar-rl-train ，私有。本机 checkout 为 `C:/Users/lulu/Desktop/claude/mjcf/polar-rl-train`。

初次归档的版本和试验索引均已补建。未来每次真实修复、参数/科目切换、独立试错、失败/回退和完成评测，应在新证据保存后追加提交与注释标签；未改变且健康的巡检不必制造标签。

2026-10-09人类再次明确：**所有试错、所有报告都用Git记录**。执行[全部试错与报告政策](ALL_TRIALS_AND_REPORTS_GIT_POLICY.md)。同步/最终验证回执、读者错误和后续补充报告也要提交；不能因没有新GPU实验而遗漏已保存报告。同一阶段可合并，已有同SHA内容可索引引用，健康无新报告仍无需单造trial。

先保留旧代码/config/来源检查点哈希，再保存新代码、完整配置、实际参数回读、协议/seed/环境数/时长、逐环境结果、失败样本和部署/拒绝状态。说明“修了什么/为什么/怎么验收/还缺什么”，不要只写奖励升高或 success=1。其它 AI 的身份不明时标未知，原文声明与实际测量区分。

将本次改变的代码/配置及报告拉到本机仓库的新版本目录，避免覆盖旧归档，写说明文件后用 `archive_tools/record_experiment.py --id 唯一英文ID --title ... --kind ... --note-file ... --files ... --push`。可以按专项合并配对证据，但每次真实试错有独立 ID。标签不可覆盖，旧失败不得删除；代码、结果缺失时明示证据等级。

GitHub 登录只使用用户本机已有 Git credential helper；SSH 凭据通过授权会话环境使用。不能将凭据写入仓库、远端交接、报告或日志。权重/大型轨迹保留来源与实际已有哈希索引；不要为打标签中断训练、增加预算、复制 canonical 账本或运行旧 one-shot 接管脚本。

原生产继续受真实进程、完整检查点保存边界和唯一有效训练预算约束。此文仅是记录工作流，不是新训练授权。二小时巡检及阶段晋级条件仍按当前自动化/最新交接执行。
