# PC3_CANDIDATE_BUNDLE_V1 — pre-implementation scope

Only a new in-process, fixed-memory mathematics candidate service. Catalog: Office/ACL only; no robotics match, use file/C/Python CLI. Old C3/C2, all other cores, static seam report and saved fixtures are read-only. No pc3_cycle, dispatch backend, enqueue, driver, FSM, MPC, Power, transport/parser/worker, physics, GPU, Git, agent or parent-goal actions.

## Interface and lifecycle

- New caller-owned config/context/workspace/output, C99 and extern-C. Config default is unbound, data/time/frame convention and nonzero service session must be explicitly declared. Geometry/IMU parameters are supplied to the unchanged C3 validator, not auto-selected by the service. Binding this mathematical schema is not hardware qualification.
- Explicit `init` then `arm(SUPPORTED_UPRIGHT or STATIC_GRAVITY)`. Preserve C3's supported-prior versus actual static-gravity rule; no implicit upright fallback. No transmit binding exists. Original `pc3_command.enable` is observed unchanged; missing/unknown/disabled rejects without P25 work. Disabled, clock, source, alias, core and other errors latch the candidate service until explicit init+arm, not an automatic restart.
- Exact call order: estimator_update (which invokes its own view for held packets), p25_step, original_dc_clip into a distinct array. No estimator reimplementation, extra prediction or changes to frozen P25 data. An update's state view predicts only state14[0:7]; remaining components/gyro/derived roll remain from the source epoch.
- Bundle copies STATE14, REF14, MATH row6, GUARDED row6; internal raw shaper_v/w/a/yaw_integral and result effective shaped_v/w/a are separately named. Row order LH,LC,LW,RH,RC,RW; state deltas remain crank-minus-hip. Neither layout binds physical front/rear, signs, reducers or CAN IDs.
- `candidate_math_valid` is distinct from `send_permission`; the latter is always false on usable outputs. Faults zero all candidate payload/valid, retain only current status/clock diagnostics. There is no cached output replay, no accepted previous fallback and no actuator request. Work intermediates are never accepted outputs.

## Coherence and time

- Caller supplies matching packet/drive session and frame identities, nonzero, in addition to equal source sampled_us. Session must equal the explicitly configured session. New source frames must have increasing frame identity/packet sequence/stamp; held same-epoch frames must preserve raw payload and drive bytes. A later delivery may have later arrival_us; expose this observed delivery, not a rewritten source stamp or an invented first-arrival time. This is a producer contract, not wire authentication or hardware sampling proof.
- Original command sequence is nonzero and strictly increasing on successful control ticks; exact same-now request is not returned as a fresh cached candidate. Underlying P25 requires exactly10000us between computations; no generalized-period or monitoring-while-disabled mode is added.
- Source, observed arrival, estimate/computed, drive, mean-window begin/aperture/count/sequence plus raw gyro and held-attitude-roll epoch tags are explicit. Raw gyro is the declared-aperture boxcar payload with time labeled at window end/source epoch (bootstrap may declare aperture0/count1). It is not an instantaneous packet-end gyro, is not asserted to share an instantaneous body frame with endpoint encoders or aged STATE, and is not rotated into the aged body frame.
- Available monotonic u64 ns callback with a declared disjoint opaque storage extent; phases ENTRY/AFTER_ESTIMATOR/AFTER_P25/AFTER_DC/FINAL. External cycle_start_ns may predate entry. Positive per-call budget uses subtraction without start+budget overflow. ns/1000 flooring feeds the old API; every input us stamp used in ns checks must multiply without overflow. Full-ns age/command-expiry checks dominate and may be stricter by<1us than old floor-us checks.
- Check clock, caller budget, sensor/drive age and command issued/expiry before/after the stages, including the last poll before publication. No post-return, driver, WCET or whole-control-chain claim. Loss/backward clock latches; zero ns with available=1 is a legitimate epoch.

## Ownership / limitations

- Inputs/options/config, context, workspace, output and full clock opaque storage are disjoint and exclusively owned during a call. Copy-only output; mutation of caller input or returned arrays cannot alias service state. Structural overlap returns ALIAS; overlapping output is unusable and is not cleared through an input. Context overlapping a source is not modified merely to latch it; caller must reinitialize disjoint storage. Valid pointers and sizes are a native-C precondition; no arbitrary-address probing or race protection.
- C3 mathematical states may advance before a late candidate fault; that fault latches and no candidate is published. This is not an external commit/abort or actual-held reconciliation API. No new normal/contact/operator/actuation permission, cue cap, physical calibration or complete dispatch qualification.
- QA: unchanged3200 raw fixtures and saved C3/P25 results, plus bounded native/alias/time/lifecycle tests; actual C++ linkage. New M4/M7 compile-only facts separately recorded. No old executable or SDK is run. PH5 and all full-chain/runtime/BSP qualification remain pending.
