# MOD4 训练效率复盘与计划 v1.1 修订依据

日期：2026-10-07，北京时间。状态：审阅材料，不授予训练、预算交易、源码修复或 MoE 接管权限。

用户本次允许在计划中再加 100 小时，并要求反思累计约 100 亿步后科目与效果落后的原因。新增时间授权与训练路线批准分开：新增 360000 秒记录为待安全应用的第六次授权，总计划授权 230 h；canonical 当前仍是 130 h。本次仅读取实际账本/日志和修改审阅文件，没有写账本、启动 GPU、PPO 或修复生产源码。

## 1. 结论与责任

现有证据支持：我们将大量学习投在窄范围任务上，相关技能随后又发生遗忘；目标度量与连续奖励有过缺口；阶段切换、评测和监督器造成较大的现实时间成本。无历史的状态估计是重要待验证短板，但不能单凭结构推断它是所有低效率的主因。增加时间只提供试验额度，不能自动纠正这些问题。

我此前没有足够早地明确专家边界、科目训练量、部署反馈状态估计和稳定续训节奏；把“当前数据/模型准入”和“旧能力保持”混在阶段推进中，又在暴露遗忘后靠连续混训反复补救。部分有限性能阈值曾成为学习否决，之后才调整为 SCUT v4 诊断；监督器又把显示文件变化当作整个源检查失败。应改进的是学习组织与监督实现，不能把所有不进步解释成算力或时间不足。

华南虎的公开模型覆盖范围显著更广，这个差距应正视。但其公开材料不是同一 MOD4、DR、seed、失败标准与预算下的全科统一成绩；作者也记录了旋转平移取舍和飞坡限制。不能从模型文件名、演示或迭代上限推断其全部科目已毕业、只用了多少数据，或保证我们增加 100 h 后能达到同等结果。[原始模型记录与链路](https://github.com/scutrobotlab/wheeled-legged_RL/blob/b8ff79f3df855faf9dc92f4a282bd80c42649466/pretrained/26_infantry/readme.md)

## 2. “100 亿步”的口径尚未成为可信总账

本轮远端读取时间 epoch=1791303003.5123236。界面实际代码：

```python
cumulative_steps = iteration * num_envs * steps_per_env
```

23936×20000×24 = 11,489,280,000，约 **114.89 亿**。这里的 iteration 是从完整来源继承的编号；当前环境数与采样长度不能自动代表所有祖先运行。历次环境规模变化、不同来源重基、失败分支、预检丢弃和旧迭代偏移都不能由这个乘积识别。

最新 auto0390 真实日志的 Total steps 为 **151,680,000，约 1.5168 亿新策略步**：来源 start23621，最后学习 header23936，316轮×20000×24。日志同时记录 collection=21.701 s、learning=0.149 s、iter=21.85 s。这是该运行新增量，不是全部历史量。最终完整保存 receipt 指向 model23936，PID608594；此处只核对 receipt 和正常退出日志，未把未回放的新策略称为能力改善或新 CPU 有限验证。

不能据此断言全部历史没有 100 亿实际交互，也不能继续把 UI 乘积作为已经审计的总数。即使后来证实累计真实交互达到该量级，也不等于每一科都获得了这份训练。

S0 要建立以下独立数字，替代一个“累计步数”：

| 数字 | 正确口径 |
|---|---|
| 全实验新增交互 | 按 run ID、实际 num_envs、rollout 长度与完成轮数汇总；来源继承编号不重复累加 |
| 正式保留训练链 | 按 init SHA→实际保存 SHA 的有向图追溯；预检和未选分支独立标注 |
| 每科训练量 | 实际 command/mode/地形/DR 样本计数与有效时长；配置比例只是期望，不能代实测 |
| 丢弃/失败学习量 | 保留实际成本与原因，不把没有进入最终来源的学习归给当前专家 |
| 物理子步 | 本机每控制步20子步，另列；不当作20倍策略新样本 |
| 优化器样本访问 | 多 epoch 重复访问 rollout，另列；不当作新环境交互 |
| 现实时间 | 学习、冻结评测、启动/保存/退出、排错、等待分别计量；不改历史学习账本 |

存在无法重建的旧日志时报告缺口、已证实小计和边界，禁止用 UI 估计补齐。总实验成本和保留链成本都公开，不能只展示筛选后最佳分支的低成本。

上述实际系统性遗忘不是一个任意通过率毕业线。历史编码器可能改善噪声/延迟与地形适应，但5帧未必足够、不能预知无可用感知的障碍，也不能识别所有不可观测动力学。必须实测，不能把它作为下一次失败的通用解释。

## 5. 网络与上游比较中的纠正

我们已经使用 asymmetric/privileged critic。缺少的是部署侧历史状态估计与相应辅助监督，不能说“完全没有privileged学习”。复旦固定版本5帧分支用独立encoder optimizer监督真实速度，actor latent.detach；这不是已经确认的完整teacher动作蒸馏。[辅助损失](https://github.com/yly-true/fudan_rl_wheel_leg/blob/8204e853dfd2ed06d85a322e1a998c3d20a3be2c/plane/wheel_legged_gym/rsl_rl/algorithms/ppo.py)、[历史actor](https://github.com/yly-true/fudan_rl_wheel_leg/blob/8204e853dfd2ed06d85a322e1a998c3d20a3be2c/plane/wheel_legged_gym/rsl_rl/modules/actor_critic_sequence.py)

华南虎轻量flat保存配置是128–64–32，而2026-07-23_16-23-21 rough_rotation_stair非轻量保存配置是 **256–128–64，与我们当前隐藏层相同**；其actor/critic均如此。该rough配置还明确从flat model8000启动。当前MOD4 manifest的LR=.0001、adaptive、24步、5epoch/4minibatch、KL=.01、value_loss2也与该basic PPO配置大体相近，不能把源码默认fixed或轻量网络泛化为所有实际运行差异。[轻量flat配置](https://raw.githubusercontent.com/scutrobotlab/wheeled-legged_RL/b8ff79f3df855faf9dc92f4a282bd80c42649466/pretrained/26_infantry/flat_and_rotation/2026-07-29_23-20-03/params/agent.yaml)、[rough保存配置](https://raw.githubusercontent.com/scutrobotlab/wheeled-legged_RL/b8ff79f3df855faf9dc92f4a282bd80c42649466/pretrained/26_infantry/rough_rotation_stair/2026-07-23_16-23-21/params/agent.yaml)

SCUT控制20ms/物理5ms与MOD4控制10ms/物理.5ms导致每模拟秒物理工作量不同；机器人结构、碰撞、接触积分和硬件包络也不同。这解释部分wall成本，但不是用来回避奖励、课程和监督效率的理由。不能直接声称本机wall必然慢10倍；不能未独立证明闭链和接触等价就将dt改大。

## 6. 计划新增的架构对照 S1A

先固定已验证来源、任务、DR、reward/PPO，比较三个候选：

1. A0：现有35单帧 MLP，保留基线。
2. A1：5帧可部署反馈→小encoder→3维Body速度估计；用实际特权线速度监督，critic保持既有独立输入。
3. A2：同历史接口、同encoder，但仅PPO端到端学习latent；用于区分“增加历史”和“辅助监督”的贡献。

首工程接口35×5=175历史，候选encoder175→128→64→3；actor输入[current35,latent3]为38。latent首先解释为速度估计，不包装为已经辨识质量、弹簧和摩擦。100Hz五帧相邻跨度40ms；延迟压力与响应不足时独立比较10帧90ms，不能未经评审自动扩大窗口。

必须核实最新帧顺序、实际时间戳、episode reset初始化、选中行清缓存、lastaction语义、缩放、特权速度的物理点/坐标系与标签索引；不能假定我们critic的前3维就是速度。部署actor/encoder只用机器人可用反馈，无真实线速度/地形ID注入。critic清洁特权是训练用途。

原actor首次扩维使用新增latent输入列零初始化/等价迁移，并实际验证初始动作与旧模型一致；encoder有新optimizer，不能称完整继承旧单策略optimizer。A1的独立监督损失与actor detach规则明确，A2的联合梯度明确；完整保存包括两optimizer及RNG/history配置。必要学习、包括encoder监督均计同剩余预算。

按完整方向/退化/DR/样本量和wall而非总reward选择；无证据不替换全部专家。旧五帧候选文件仅说明曾写过实现，不能作已生产启用或验证的依据。专家最终接口先在S1A确定，门控再按同一可部署信息实现；结构变化写入批准计划，不边训边偷偷切换。

## 7. 追加100h如何用

明确时间授权ID：USER_ADD100H_20261007_6TH，+360000 s。总计划授权由468000→828000 s（130→230 h）；当前账本未应用这次扩展，已计学习不变。根据本轮实际剩43.192113 h，追加后的可用计划额度约143.192113 h；拟议各项上限合计143 h。所有上限都可提前停止，不要求花满。

批准后的S0在完整保存/无孩子/active明确/同canonical两锁安全边界唯一应用这次登记。先检查扩展ID与前后总额，已应用则核验复用，不重复增加。需让新计划执行器按实际授权登记验证，不能复活只认130h的旧入口。

额度增加后仍优先：核实数据口径与监督边界→历史状态估计对照→E0/E1各自任务与DR→门控与公平对照。4π移动、更难地形、自救和洞的额度是条件预留，不能因有100h直接跳过真实reset/参数/硬件合同。缺硬件弹簧、负载或净空测量时，明确暂停对应组，继续其他已批准可验证项。
