# MOD4 当前门槛与华南虎开源逐项审查

审查日期：2026-10-07。当前生产取证时间：2026-10-07T17:05:26.257078+08:00。华南虎来源固定为 `scutrobotlab/wheeled-legged_RL@b8ff79f3df855faf9dc92f4a282bd80c42649466`；重新获取并核验十份源文件/保存配置。读取当前 MOD4 208 文件冻结索引，将选取的实际训练 hook、任务、v4 准入与两个接续监督器逐字核验，做静态及 CPU 反事实审查。此次新增 GPU 探针/PPO/预算操作/信号/运行配置修改均为 0。

## 结论

有过度保守的规则。最突出的是：当前已采用 1ms 的学习仍继承“候选物理时钟验证”的全批零任务终止规则。单个环境普通摔倒、底盘着地，也会被提升成全批保存退出事件。这与华南虎公开入口的逐环境失败重置、持续 `runner.learn` 有实质差异。以前频繁完整回放、保存审查后没有现成接续器，也已造成可见现实时间空档。

当前有限性能指标大部分已改为诊断；世界方向某个样本略超 .05m/s 并不会触发当前连续监督器 attention。因此不能把当前所有等待都归因于“必须100%”。当前 S2 D1/D2 已有完整好结果；D3 只有 CPU 组件，实际 SDK/PPO/执行器尚未完成，是继续停留同一组 DR 的直接工程原因。6h 是该接续窗口的上限，并非必须学满才能推进。

闭链 2mm 是 MOD4 自定的机制一致性合同，未找到它是华南虎作者规定的健康门槛。华南虎模型的有限误差统计可以用于质疑“一次2mm最大值是否足够宣布整个时钟不可用”，但不能直接证明 MOD4 的10mm健康，也不能直接恢复被拒绝的2ms/2.5ms/5ms。

## 当前代码行为的 CPU 证明

复制且SHA核验的当前代码，用真实24827三份返回数据及合成反事实做14项CPU审查，未初始化CUDA：

- 三份实际flat/spin/world都通过v4，无attention；world64/64、最大绝对净cross .047304944m/s。
- 把一个完整圈cross改为 .050001m/s：原事实63/64，v4仍pass且attention=false，说明当前并不机械要求100%。
- 把48个±2rad/s样本全改为明显cross偏差：16/64，模型/数据v4仍pass，但外层attention=true，属于系统性旧能力审查。
- 即使closure仅 .9mm、mimic .0019rad、callback完整，合成一个普通 `terminated` 事件仍请求全批STOP_AFTER_SAVE；timeout不请求。这是CPU控制流验证，不是新增物理摔倒测试。
- 非有限、接触数据不一致、mimic .02rad仍拒绝，保护没有因有限性能诊断而消失；实际参数初末检查在代码中保留。
- 当前直线检查另有偏松处：合成 +1.5m/s 命令、仍正向但仅1.15m/s、误差 .35m/s，不会attention。正反符号正确并不足以证明旧技能保持，应与同SHA锚点的误差变化比较；不要再造单个绝对性能硬否决数值。

## 建议优先顺序（尚未部署）

1. **先分开普通失败与硬异常的监督规则。** 普通摔倒/触地按环境终止、罚分、reset，整体持续学习；记录各原因计数、episode失败率及趋势。NaN/OOM/引擎异常、实际源/参数/数据损坏、闭链/传动机制超限继续保存保护及隔离审查。不要仅汇总一个terminated mask宣告全批物理失败。
2. **分开学习状态、固定技能验收及严格目标事实。** 完整有效失败轨迹也应能用于分析；成熟锚点回归失败须报告，当前新课失败不应自动冒充“无效数据”。原严格world与pure事实继续计算；跨seed/profile稳定改善、小残差可按已授权接受实际够用，系统性退化需诊断。也补上正向但明显欠速的保留审查，避免过松。
3. **在训练期间准备下一阶段和后继入口。** 保存后立即在唯一启动权/两锁/明确账段边界接已准备范围；评测交3060，固定source复用，健康同范围不等待桌面。D3的SDK/reset/cache/时间单位/PPO合同应优先完成；6h cap是风险上界，不是毕业时长。
4. **普通终止借鉴持续时间过滤。** 候选按秒定义并先独立验证，仅普通姿态/接触，不将SCUT .4s不经验证套到MOD4，也不延后数值/机制保护。100Hz与50Hz需要换算。
5. **闭链阈值另行论证，先补原因/持续时间/分布。** 比较中位/P95/P99/max、超差占比、单链最长持续时间、reset冲击、传动/足迹及行为偏差。保留2mm原事实和已有失败；若要修改机制合同，应以独立计划补充获准，再验证长段随机PPO，不能拿短窗或SCUT10.25mm直接宣告安全。
6. **保存开销先量化再改。** 区分常规完整save耗时、统计读回GPU同步、冷启动及显存占用；当前save25及15s预算保护保持。没有实际IO占比就先不以save500替代保护。
