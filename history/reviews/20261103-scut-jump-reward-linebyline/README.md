## 总公式与符号

对每个并行环境分别计算：

`r_t = step_dt × Σ_i weight_i × postprocessed_raw_term_i`。

先算 `rew_*`，状态机再替换、缩放或增加原始项，V14 再处理可选小陀螺平移项，随后乘 dt，按 cfg.rewards 的键过滤并乘权重，处理非有限值，最后求和。不存在“只要写进 reward_additions 就自动进 PPO”的规则。`failure_event`、`release_vel_z_shortfall`、某些 `leg_retraction` 返回的是正的代价，负权重才把它们变成惩罚。正权重的指数项才是在误差小时给高分。

`N` 为环境数，车轮数组一般为 `[N,2,...]`；`mean(dim=1)` 是平均左右轮，不是平均所有环境。`w` 是世界坐标，`b` 是身体坐标；`heading_b` 的原点和yaw跟随机身，roll/pitch被移除，xy面保持水平。环境辅助函数还把轮位置的y分量置0，所以这些“腿长”实际是该平面投影的范数，不能讲成完整三维腿向量长度。`clamp(x,min=0)` 是只取正超量，`torch.where` 是逐元素选分支，mask 为0时这一奖励不给分。

## 最直接的上阶奖励在鼓励什么

Stair 提供七种命名类型：成功事件、失败事件、快速成功、相对台面身体高度追踪、单步上升进度、轮子超过参考台面高度、轮子水平接触力超量；另支持活动期常数。它以扫描估计的台面高度为参考，把相对该台面的身体高度设成命令。高度进度只计上升，不扣下降；左右轮抬高奖励取均值，单轮较差会拉低平均但不等于双轮硬约束；水平接触力惩罚不识别具体台沿材料或接触面。

Stair 的成功事件来自：处于上阶状态、双轮历史接触力峰值各过阈值、身体相对台面高度达到目标减容差，保持配置时长。该条件不查询接触是否来自台顶，也不查询轮子完整 footprint 是否跨过台沿、是否第一次飞行、落地速度或姿态是否达标。因此这是该状态机的训练事件定义，不能直接替代本聊天270mm验收。

JumpTakeoff 把任务分为 IDLE/PUSH/TUCK；能奖励向上速度、正向加速度、释放速度、峰值、弹道参考跟踪和收腿。其弹道只规划垂直高度与速度，不提供上阶的水平落点。`wheel_airtime` 实际是当前双轮离地高度布尔量，未累计腾空时长。源文件还提供可选外力/速度辅助；是否有辅助必须查实际 assist.enabled，不能把辅助运动算成纯策略。公开上述上阶模型的 assist=false。

Airborne 在合适窗口改变普通奖励，并提供落地前轮速、减小轮扭矩、轮子前后居中、关节限位、接触冲击与滑移等项。当前 V14 的 target_height.enabled=false 和 landing_trajectory.enabled=false，不能把留在配置里的目标抬升/缓冲弹道当已开启。

## 读取时需要特别注意的数值

- 多数 `exp(-error²/sigma)` 的 sigma 是直接分母，不是代码自动平方后的标准差。公开模型紧高度项的分母为0.001；误差5cm时约为0.0821，乘0.02控制步长后约0.00164（权重1，仅这一项）。
- `wheel_zero_torque_exp` 则确实是 `exp(-(max_abs_torque/1.5)²)`。`landing_wheel_body_x_positive` 是 L1 形式 `exp(-deficit/sigma)`。不要统一套成同一种高斯。
- 公开模型高度项还含 `-1 × (10×height_error)²`，没有同样的±0.15m误差截断；紧指数项使用截断误差。两者的远离目标行为不同。
- `no_fork` 是左右轮在身体 x 方向错开的约束，公开阈值5cm；不是要求双轮跨台沿，也不是世界x进度。
- Stair 的 fast_success 扣除 success.duration_s 时，默认取0；生成成功事件的持续时间默认取0.3。这是两段代码的不同兜底值，应由显式配置统一，不能在解释中悄悄合并。
- Airborne 的轮接触计时在轮子仍低但接触力短暂消失时保持原值；base 接触计时也会保持。它们不是严格“每一步都持续有力”的计时器。
- 所有事件奖励同样乘 step_dt。例如原始成功事件1、权重100、dt0.02，单次最终贡献是2，不是100。
