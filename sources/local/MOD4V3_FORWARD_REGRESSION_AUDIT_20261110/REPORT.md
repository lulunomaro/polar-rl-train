## 4. 策略数学：小参数变化如何引出大闭环变化

令父策略为 π0，新策略为 π1，各自运行产生观测分布 d0、d1。对策略动作均值有精确分解：

`E_d1[π1]−E_d0[π0] = E_d0[π1−π0] + (E_d1[π1]−E_d0[π1])`。

在当前 DR+5ms 前进条件，轮子两维：

- 实际各自轨迹的总动作变化为 **-0.88225、-0.94050**。
- 给双方完全相同的父策略轨迹观测，新策略的直接参数效应反而是 **+0.01560、+0.03923**。
- 余下的状态分布效应为 **-0.89784、-0.97973**。

所以新权重不是简单地对所有输入统一减小轮速。改变腿部控制、姿态/轮速状态、上一动作反馈后，闭环进入较慢的运行状态，再继续输出较低轮速。当前 actor 的35维没有直接 base vx，靠角速度、重力、关节速度和上一动作间接感知；对接触、滑移和姿态变化容易发生这种分布偏移。上一轮动作输入的局部敏感度确实较大，但局部 Jacobian 不是完整机器人稳定性证明。

为了进一步定位，执行 `policy_factor_r1`：160 环境，权重完全冻结，将腿部4维与轮子2维输出交叉组合，其他协议保持不变：

|固定输出组合|名义零延迟前进|当前 DR+5ms 前进|
|---|---:|---:|
|父腿 +父轮|1.68826|1.66834|
|父腿 +新轮|1.66926|1.61050|
|新腿 +父轮|1.59955|1.47139|
|新腿 +新轮|1.55272|1.25514|

当前 DR 下，只替换轮子损失 .05784m/s，只替换腿部损失 .19696m/s，两者一起替换另有 **-.15840m/s 交互项**。这比“只调大轮子动作”更支持腿部姿态与轮速闭环配合发生改变。混合策略仅用于诊断，未做 yaw/全任务验收，不是新训练模型，也不是可部署修复。它定位敏感位置，不能把这些数值硬分成原始 PPO 梯度的百分比。

旧 7a 20min 在相同父观测上的轮子动作也已经明显降低（约 -.74/-.77），forward KL 约13.5；本次新5min的同观测 wheel delta很小，forward KL约.12。旧试验包含更直接的参数退化；小学习率减缓了它，却未防止闭环退化。

## 5. DR 实现：三处已实际读回的问题

`dr_readback_r1` 使用4环境，不加载策略，没有 optimizer、没有 physics rollout，只重复调用同一 DR 写入函数、读取原生属性并调用外力更新。源码是当前训练支持目录快照。

### 5.1 COM 是随机游走，未围绕默认值重采样

`scut_flat_joint_friction_env.py:126–134` 读取当前 `get_coms()`，再 `+= U(-.01,.01)`。因此不是每次在名义 COM ±1cm 内独立采样，而是：

`c_N=c_0+Σδ_i`，每坐标 `Var(c_N−c_0)=N·(.01)^2/3`。

32次额外调用后，单坐标理论标准差32.66mm；本次4环境的实际单坐标最大变化为 **72.528mm**，第32次末值最大变化67.838mm。实际重置也走同一函数，所以环境动力学会依赖此前重置次数。这里只测32次，不把理论无限累积冒充已观测的历史最大值；也没有据此宣告旧冻结策略无效。

这会使 episode 后的训练分布不同于开头固定评测分布，也会使继承 critic 对当前动力学的估计发生偏差。其对历史每个模型的累计影响没有保存轨迹，不能倒推精确份额。

### 5.2 摩擦分组写入互相覆盖

`_add_joint_friction()` 每次从整张 default 表开始，只向当前组加随机量，然后用全量 joint_ids 写回。依次腿→轮→被动关节，最后一组擦除了前两组。

本次**原生** `root_view.get_dof_friction_properties()`（非仅 Python 缓存）读回：

- 主动腿4关节：static/dynamic/viscous 全部0。
- 轮2关节：static/dynamic/viscous 全部0。
- 被动8关节：static .02519–.04990，dynamic .02519–.04360，viscous .00536–.01247。

旧 `get_dof_friction_coefficients()` 在新 API 下返回全0且提示deprecated，不拿它覆盖新三列属性读回。声称“主动腿和轮已加50%摩擦”与实际不符。此问题降低/改变了随机化，而不是证明它单独直接拖慢前进。

### 5.3 外力持续时间没有递减

`_update_external_wrench()` 只有 `hold.clamp_(min=0)`，没有 `hold-=1`。事件设置10后持续为10，直到reset或下次事件换一组力。本次触发后连续调用25次，hold四环境都仍为10，力/力矩完全未变；按20ms时钟超过了声明的0.2s持续期。

因此训练实际包含持续负载段，不能把它描述为10步短推力。固定消融去外力只能小幅改善新策略，说明也不是单因子解释。

### 5.4 观测噪声与 critic 的实际语义

实际35维槽：0:3命令、3高度、4:7角速度（乘.5）、7:10重力投影、10:16关节位置、16:20腿速（乘.1）、20:22轮速（乘.1）、22:28上一策略动作、28:35模式。

noise文件在已经缩放的观测上加噪，而summary把4:7/7:10命名为orientation/base_ang_vel，与实际相反；“last_action±1”也实际加在20:22轮速，而不是22:28动作。当前f=.25时，轮速观测噪声±.25相当于原始±2.5rad/s，腿速±.125相当于原始±1.25rad/s，角速度±.0625相当于原始±.125rad/s。应按固定 SCUT 参考配置核对意图，不能仅改 summary 就当作数值已对齐。

critic额外量里，delay写全0、mass scale写1、material写固定.9、PD gains写固定60/2/.6，实际却随机。它不是 actor/critic维数错误，但这些特权量没有提供所声明的环境辨识信息。critic仍可能靠状态推断一部分，不能据此断言必崩。

另外两处源级问题有明确路径，但本轮未单独量化：力矩噪声在每2.5ms直接累加到10ms保持力矩且在限幅后加入；零力矩恢复逻辑先清torque，再由父类PD刷新覆盖，不能可靠实现整段零力矩。两项应在直接修复DR时核对；不拿它们替代已完成的能力证据。

## 6. 物理与控制：不是电机最高速度卡死，但显式轮速环需要处理

当前脚本保持MOD4v3资产、总质量14.29414kg、物理步2.5ms、策略20ms、PD100Hz、TGS32/4，6维动作顺序及电机包络不变。没有换plant或提高终止容差。

轮半径 .0625m，2.2m/s理想滚动轮速为35.2rad/s，低于no-load55.3557rad/s，对应理想3.4597m/s。该速度处正驱动包络仍可到平台5.7759Nm；因此不是简单的空载转速硬上限。瞬时接触牵引、滑移、姿态与制动仍可能限制速度；用`rω−vx`只能做差值诊断，不能代替轮接触点真实滑移率。

物理tick记录揭示：名义前进父策略100Hz轮速标准差13.45/10.91rad/s、主频50Hz、扭矩平台饱和约64–66%、制动约47%；新策略约48.75Hz，饱和约51–54%。所以平均扭矩约1Nm不代表没有高频饱和。

解释性单轮模型（不当作整机特征值）：

`J·dω/dt=Kd(ω*−ω)`，显式零阶保持离散后 `e[k+1]=(1−Kd·h/J)e[k]`。

以轮子惯量量级+.armature估计 `J≈.00175191kg·m²`、`Kd=.6`，100Hz得极点约-2.425，200Hz约-.712，400Hz约.144。全机器人接触有效惯量、关节轴投影和非线性限幅会改变精确结果；这个简化模型解释为什么轻轮/滑移状态容易交替振荡，**不宣称整个PhysX机器人一定线性不稳定**。

`physics_pd_r1` 是固定权重内存诊断，名义参数，不改生产PD：

|前进2.2条件|父权重 vx|新5min vx|
|---|---:|---:|
|100Hz、零delay|1.66107|1.43613|
|100Hz、5ms buffer|1.66958|1.47897|
|200Hz、5ms buffer|1.81413|1.26575|
|400Hz、5ms buffer|1.75771|1.12899|

400Hz大幅降低轮速振荡和饱和，却让新策略更慢。因此应在既有100Hz部署口径内先处理数值离散/反馈一致性，不能直接把“改400Hz”当修复。PD消融同时改变腿和轮的刷新频率，也不能把全部速度差归到轮子一处。位置有限差分与世界速度均值接近，排除了大幅速度读数假象；并未完成所有USD轮碰撞几何与MuJoCo接触一一等价验证。

## 7. 奖励数学：存在不利机制，但不能直接说慢走更优

实际线性跟踪（未乘dt）为：

`e=v_cmd−v_x_body·cos(pitch)`

`r_v=1.2·exp(−clip(e,−1,1)^2/.5)−.1·(.25e)^2`

即平方项实际系数是 **-.00625e²**。不是看到配置-.1就当作-.1e²。

当0<e<1，增加forward speed的即时奖励斜率为 `4.8e·exp(-2e²)+.0125e`；e>1时指数项恒定，只剩 `.0125e`。例如e=.5斜率1.4619，e=1.2只剩.015；e=1边界不光滑，应区分左右极限。退化越过1m/s误差以后，指数项不再区分更坏速度，恢复信号变弱。这里是奖励地形分析；PPO使用回报/优势更新，不是直接把这个导数反传过物理引擎。

慢下来节省了一些平滑/能耗惩罚，却没有补回直行跟踪损失，**直行总奖励实际下降**。这不支持“当前奖励下慢走已经是更优解”的断言。旋转任务的奖励和速度改善、总体混合任务的优化方向，仍可能牺牲局部前进能力；没有原训练advantages，不能宣称已经抓到逐样本梯度根因。

当前代码30%gyro（15%低+15%高），30%标记为high-speed，其余40%普通命令。高速组的wz实际均匀[-2π,2π]，并非注释所说纯直行；约10%的standing掩码保留在高速/普通组，gyro组则清除standing。

由源码独立采样可算：活跃高速组占27%，正向高速占13.5%，其中`|wz|≤.1rad/s`只占**全部重采样约0.215%**。此数只算正向高速特殊组，普通heading组也可能进入近直行，不是整个训练的直行占用率。height均匀.20–.42m，固定.28±.02区间占18.18%；训练命令每5–15s重采样。与固定.28、2.2m/s、wz=0评测存在具体覆盖差异。分布正反符号对称，但机器人几何、COM、策略与接触不必对称，所以前进与后退可受不同影响。

实际 γ=.99、λ=.95、rollout24×20ms=.48s，GAE权重递减γλ=.9405，对应几何权重面积时间约.336s，discount面积时间约2s；它们不是硬截止。持续负载/COM跨reset漂移、延迟改变和继承critic，可能让短rollout更依赖bootstrap估计，但现有数据不足以证明“必须重置critic”。

旧7a的actor相对父L2：5min1.38398、10min1.84487、15min2.20642、20min2.44133；saved LR曾从父1.139e-4升至2.563e-4。当前安装PPO的adaptive schedule会在低KL时将LR乘1.5，所以上限高不等于实际用了上限，但也不是始终小学习率。

本次固定3e-5、clip=.1、epochs3使5min actor L2仅.17814，STD近似保留，仍发生闭环退化。因此只降LR已经实测不足。PPO clip限制单轮surrogate激励，不保证跨67次更新的累计KL或某个能力不下降；final KL不能拿来冒充单次更新越界证据。

**value_loss_coef=4不直接把critic梯度加到actor。** 当前actor/critic是独立网络，源码分别做grad norm clip；critic通过优势估计间接影响actor。不能用“value loss大所以压垮actor”当作现成结论。Adam状态继承、critic偏差、熵系数的实际贡献需要原rollout或针对性无更新的优势分析；本轮没有凭空归因。
