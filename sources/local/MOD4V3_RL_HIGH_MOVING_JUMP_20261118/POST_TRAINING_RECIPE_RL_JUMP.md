# 同构型轮腿机器人纯神经网络 RL 大跳与移动连跳标准后训练配方 (`POST_TRAINING_RECIPE_RL_JUMP.md`)

> **适用机型**：与 `MOD4v3 / HW300N60_R3` 同构型的并联四连杆（含气弹簧蓄能）+ 双差速轮毂驱动轮腿机器人。  
> **配方定位**：在不改动、不退化已有全地形平顺运动基座策略（`E0`，如 `c874`）的前提下，通过 **MoE 模式位路由 + 3 轮闭环 DAgger 热启动 + 反作弊渐进 DR PPO**，在单台多核 CPU（或 GPU）上高可复现地训练出**零状态机、零特权输入、零擦地的纯神经网络原地大跳、边移动边连跳与 `16~20 cm` 实体跨栏策略 (`E_jump`)**。

## 一、 硬件接口与零混叠本体观测契约

### 1.1 底层物理与执行器频率契约（严禁降频）
1. **物理仿真步长**：`dt = 0.0025 s`（`400 Hz`），保留完整并联四连杆闭合连接约束（闭合误差 `< 10 mm`，实测 `~2.0 mm`）与并联气弹簧（MOD4v3 为 `2000 N/m`；迁移至新质量 $M_{\text{new}}$ 机器人时按 $\frac{M_{\text{new}}}{M_{\text{ref}}}$ 线性缩放气弹簧刚度与腿部 PD 增益）。
2. **多速率控制环**：
   - 策略网络推理：`50 Hz`（每 `8` 个物理子步更新一次 `6D` 动作 $\mathbf{a}_t \in [-6, 6]^6$）；
   - 腿部关节位置 PD：`100 Hz`（每 `4` 个物理子步更新一次力矩，`Kp = 60, Kd = 2`，经连续关节差角限幅 `[0.1727, 1.7509] rad`）；
   - 轮毂速度阻尼伺服：`400 Hz`（每个物理子步更新，`Kv = 0.6`）；
   - 电机外特性裁剪：每个物理子步严格按直流电机堵转斜坡与峰值扭矩包络裁剪输出扭矩。

### 1.2 零混叠纯二值跳跃触发接口 (`obs_35` + `obs_history_420`)
Actor 输入仅包含当前 `35D` 本体感受观测与最近 `H = 12` 帧（`0.24 s`）滑动历史队列 `420D`（**零世界高度 $z$、零外部计时器、零接触传感器输入**）：
- `obs[0:3]`：`[cmd_vx, cmd_vy, cmd_wz]`（支持 `-0.60 ~ +1.25 m/s` 边移动边跳）；
- `obs[3]`：`height_cmd * 5.0`（常规巡航 `0.28 m -> 1.40`，跳跃期间保持恒定，无需外部篡改）；
- `obs[4:7]`：机体系角速度 $\boldsymbol{\omega}_b \times 0.5$；
- `obs[7:10]`：机体系重力向量 $\mathbf{g}_b$；
- `obs[10:16]`：主动关节角相对零位偏差（轮转角置 `0`）；
- `obs[16:22]`：主动关节角速度 $\dot{\mathbf{q}} \times 0.1$；
- `obs[22:28]`：上一控制拍实际执行的 `6D` 动作 $\mathbf{a}_{t-1}$；
- `obs[28:35]`：模式路由位 `[1, 0, jump_bit, 0, 0, 0, 0]`：
  - 常规巡航：`obs[30] = 0.0` -> `MoEJumpBody` 100% 路由至冻结基座 `E0`，实现**比特级零退化**；
  - 触发跳跃：用户或上层导航仅将 **`obs[30]` 置为恒定二值 `1.0` 持续 `1.44 s`（`72` 拍）后归零**。
  - **为什么不会发生时间混叠？**
    1. `t ∈ [0, 0.24s)`：`obs_history[:, 30]` 中存在唯一的 `0 -> 1` 上升沿，驱动网络进入深蹲蓄力（`CROUCH`）；
    2. `t >= 0.24s`：虽然 `obs_history[:, 30]` 全为 `1`，但此时本体关节差角 `delta` 已处于深蹲压缩态、随后依次经历高伸展角速度（`PUSH`）、悬空快收腿（`FLIGHT_TUCK`）、下落预伸展（`LANDING_EXTEND`）与触地屈膝缓冲（`SKYHOOK_ABSORB`），在关节相空间中轨迹完全不相交；
    3. `t ≈ 1.20~1.44s`：机器人已回到 `0.28 m` 稳态巡航，此时 `obs_history[:, 30]` 全为 `1`（无上升沿）且姿态处于正常站立相，`E_jump` 平滑输出巡航动作并在 `obs[30] -> 0` 时无缝切回 `E0`！

## 二、 关键动力学规律与四大必避工程陷阱（经验结晶）

在同构型并联四连杆轮腿机器人上复训大跳与移动跳时，务必遵循以下四条在 `MOD4v3` 上实锤验证的物理与优化准则：

### 陷阱 1：移动起跳误把轮子摆到质心前方导致“急刹原地跳”
- **机理**：并联四连杆髋均值角 $\text{mean} = \frac{1}{2}(q_{\text{front}} + q_{\text{rear}})$ 增大对应轮心向机身后方（$-x$）摆动。若直接套用原地起跳的 `push_mean_bias = -0.285`，高速移动时轮心会跑到质心前方 `+2 cm`，`1000 N` 蹬伸力产生水平反向制动分量，将 `0.8 m/s` 前进速度刹停并撞上实体栏架。
- **标准配方**：
  - `CROUCH` 阶段加入速度前倾偏置：$\Delta \text{mean}_{\text{crouch}} = +0.030 \cdot v_{x,\text{cmd}}$；
  - `PUSH` 阶段加入弹道前跃偏置：$\Delta \text{mean}_{\text{push}} = -0.285 + 0.120 \cdot v_{x,\text{push}}$；
  - `LANDING_EXTEND` 阶段采用**等速平衡态 Raibert 落足律**（而非驻车制动律）：
    $$r_{\text{air}} = \text{MEAN\_GRID}(\bar{\delta}) - 0.55\theta_{\text{pitch}} - 0.20 v_x + 0.16 \max(0, v_{x,\text{cmd}}) - 0.06(v_x - v_{x,\text{cmd}})$$
    确保落地瞬间轮胎落点恰好位于等速倒立摆平衡角，落地后**零倒车回滚**、直接流畅前冲越障！

### 陷阱 2：深蹲/擦地悬崖罚分诱发 PPO 习得“拒跳装死”局部最优
- **机理**：若对导轮轻触地面施加巨额阶跃罚分（如 `>1N` 即扣 `-5.5` 分）且无拒跳惩罚，高斯探索噪声在最低深蹲点附近偶发触地会使“起跳”的期望优势变为负值，导致 PPO 把动作幅度压零（不跳 = 100% 存活拿巡航分）。
- **标准配方**：
  1. **窗口关闭拒跳反作弊重罚**：在 `obs[30]: 1 -> 0` 关闭帧检查本跳峰值轮底净空，若 `window_peak_rim < 0.22 m` 立即扣除 **`-8.0`**；
  2. **双轮竖直无擦地落地才发放净空大奖**：仅当双轮真实触地、`|\theta_{\text{pitch}}| < 22^\circ` 且导轮/底盘力 `< 1 N` 时发放 `+9.5 * clr_score^1.2 * exp(-(pitch/0.22)^2)`；
  3. **连续比例式非轮胎接触罚分**：`-0.25 - 0.0008 * min(F_nonwheel, 2000)`，消除探索悬崖。

### 陷阱 3：低方差探索 `STD` 下 `Adam` 学习率过大导致单步 KL 爆炸
- **机理**：热启动后探索标准差较小（`STD = [0.020, 0.020, 0.020, 0.020, 0.030, 0.030]`）。由于 `Adam` 对梯度做二阶矩归一化，每步参数更新量约为 `lr`，经 4 层 `256` 维网络放大后输出均值变化 $\Delta \mu \approx 250 \cdot \text{lr}$。若设常规 `lr = 4e-5 ~ 1e-4`，单个小批次即可产生 $\text{KL} \approx \frac{1}{2}(\Delta\mu / \sigma)^2 > 0.18$，冲毁预热策略。
- **标准配方**：
  - **前 8 轮仅训 Critic（Critic-Only Warmup）**，且预热期使用与正式训练**完全一致的随机采样策略**消除价值分布跳变；
  - **Actor `Adam` 学习率严格设为 `6.0e-6`**（余弦退火至 `2.7e-6`），仅在 `obs[:, 30] > 0.5` 的激活步归一化优势与统计 `approx_kl`（实测全程稳定在 `0.0065 ~ 0.0093 < target_kl = 0.012`）；
  - 叠加双侧镜像对称损失 `0.35 * ||pi(mirror(s)) - mirror(pi(s))||^2`（把空中最大横滚角压至 `< 0.5°`）与干净轨迹锚定 `0.28 -> 0.20`。

### 陷阱 4：Windows 多进程 `spawn` 重复加载 `torch_cpu.dll` + `OpenBLAS` 触发页面文件耗尽
- **标准配方**：设置 `OPENBLAS_NUM_THREADS=1`、`OMP_NUM_THREADS=1`，在环境内部使用纯 NumPy 计算电机控制律，并利用 MuJoCo C 求解器释放 GIL 的特性采用进程内 `ThreadPoolExecutor(num_envs=14)` 并行采样，整机内存占用仅 `~300 MB` 且零跨进程序列化开销。
