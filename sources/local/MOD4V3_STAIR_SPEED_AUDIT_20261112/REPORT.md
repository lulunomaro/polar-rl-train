# 越训练平地越超速：只读因果调查（2026-11-12）

结论：已验证的直接控制原因是腿部输出改变了腿—轮平衡闭环的稳态车速。新策略在高站姿下补足了前进速度，但这套腿控变化迁移到低站姿时造成更大超速。新增台阶助跑进展奖励有明确向更快运动偏置；然而超速在此前Rough-v1就存在，不能把全部偏差归因新奖励，更不能声称单个奖励最优点就是2.9m/s。

只读范围：没有训练、没有修改任何生产/冻结训练源码、奖励、plant或PT。诊断输出只写入本目录。先前20m原任务仍最后确认635.524s，SSH失联后的状态待收，没有重发PPO。

## 实验方法与完整性

93次冻结回放：68个指令/延迟/高度/输出通道条件、16个几何与输出通道复核条件、9个历史检查点条件。所有案例同一MOD4v3 R3名义MuJoCo plant、2.5ms物理/10msPD/20ms策略，12秒/案例、取末4秒，固定扰动seed0。主响应含0ms与5ms动作/传感器物理延迟；通道和历史对照固定5ms。不是93个独立统计种子，不据此推断fullDR通过率。

全部93回放0重置，六闭链锚点最大误差0.100858mm。模型及原回放源码的SHA见SOURCE_IDENTITY。原始轨迹保留NPZ；独立图SPEED_CAUSE.png。诊断控制器将父/新策略6维输出的腿4维与轮2维组合，仅用于判别控制路径，不是可部署模型。

## 1. 直接控制路径：偏移跟随腿控，轮控在同一输入下几乎没增速

同指令2.2m/s、高度0.28m：

| 腿部4维输出来源 | 轮子2维输出来源 | 稳态实际m/s |
|---|---|---:|
| 父 | 父 | 2.555713 |
| 父 | 10m | 2.564087 |
| 10m | 父 | 2.912729 |
| 10m | 10m | 2.905664 |

在1.5和2.0m/s指令重复该对照，主要偏移也跟随新腿部输出；几何记录与原始轨迹见hybrid_followup。固定同一批父模型稳态35维观测输入，10m相对父模型的轮速度目标变化仅左+0.1021、右−0.1309rad/s，平均还略减；真正各自闭环运行时轮速却从约40.46/41.37升至45.93/47.10rad/s。这说明轮速的主要增加来自变化后的状态/腿姿反馈，不是同一状态下轮支路直接整体加速。

新腿控对同一输入给出不同关节位置目标，经实际力学与平衡反馈，产生不同关节/重力/上次动作输入，已有轮控在这些状态上给出更高轮速。此结论定位控制通道，并不把整个闭环简化为某一个关节偏置；交换输出仍保留腿、轮之间的动态交互。

几何上，父/10m稳态pitch约1.50°/3.79°，腿相对机身的位置与夹角明显变化；整体质心在支撑轮中心前后的偏差都只有约0.02～0.03mm。不是“平地有重力分量一直拉着车加速”或已失稳；它在更高的速度平衡点稳定下来。

## 2. 高站姿学好了，低站姿变差了

| 站立高度指令 | 父模型实际m/s | 10m实际m/s | 目标 |
|---|---:|---:|---:|
| 0.28m | 2.555712 | 2.905664 | 2.2m/s |
| 0.38m | 1.978291 | 2.221142 | 2.2m/s |

新课程的上行样本集中在0.365～0.40m、正向1.5～2.2m/s。相同网络同时负责普通平地、不同高度与全部Rough地形；没有单独平地控制器或保持旧平地行为的训练约束。高站姿能力提升和低站姿退化的对照，结合输出通道实验，支持“腿控在不同高度间发生负迁移”的解释。完整指令响应呈正向偏置扩大，倒车不是同等幅度增加；0指令的稳态漂移也从约0.0876变为0.1706m/s。

最后原生训练观察中普通平地占819/4096，名义且平地仅164/4096。较高高度、特定正向快指令的细分条件更少；不能把20%平地当成每一种高度/速度旧技能都被约束。当前stair_approach为363个环境。50%指的是宽阶reset抽样概率，不是按策略步严格占比；长时间受阻的episode会改变实际在途占比。新台阶奖励依赖是否approach、最远进展和空间位置，这些标志不直接在原35维actor输入中；同一输入控制逻辑仍需服务不同任务目标。

PPO按采样优势更新共享网络，目标不是分别保证每个固定命令误差都单调改善。这里没有归一化器漂移：PPO_EFFECTIVE明确actor/critic obs_normalization=false，actor_state_dict仅MLP及分布参数。所有对照用确定性actor，因此探索STD变化也不是这些速度差的来源。

## 3. 新增进展奖励的偏置确实存在，但不能把2.9解释成它的点态最优

实际速度项（代入原始SCUT AST、启动配置权重/尺度）：

R_v = 1.2 × exp(−min(e²,1)/0.5) − 1.5e²

e = command_vx − body_vx × cos(pitch)。原指数项的误差有±1裁剪；平方项不裁剪、不只罚欠速，超速欠速对称。

把回放状态代入该项，高度0.28m的父/5m/10m奖励速率约0.7461、0.0984、−0.2611，速度误差越大罚得越重。数值是对回放状态的公式计算，不冒充目标机训练时的逐项日志。

新增额外奖励在原scut_rough_stair_lift_env.py的_get_rewards末尾加入：

r_extra = 0.02 × min(本步新向内进展/0.02,2.2) × exp(−((实际相对高度−高度指令)/0.05)²) × valid + 0.5 × 新台阶数量 × valid。

它没有要求已经碰到或跨上台阶，外侧平地助跑就能给进展分。普通flat_terrain_mask环境不领这项；被标为台阶approach的物理平地会领。新增dense项保留了原速度项，但改变了总优化目标。高度合适、尚在推进且没有跨级时的局部计算结果：

| 指令m/s | 原速度项偏好m/s | 加进展奖励后偏好m/s |
|---|---:|---:|
| 1.5 | 1.500 | 1.631 |
| 1.8 | 1.800 | 1.931 |
| 2.0 | 2.000 | 2.130 |
| 2.1 | 2.100 | 2.200 |
| 2.2 | 2.200 | 2.200 |

因此较低指令下存在约+0.13m/s的速度偏好；因进展速率在2.2截顶，2.2指令下点态最优仍约2.2。它本身不能把2.9变为合理速度最优。它能够改变助跑/姿态的训练偏好，再通过共享策略跨状态迁移；但要量出这项对参数更新的独立贡献，需要相同预算去掉它的PPO对照，本次只读调查没有做训练。

此外gamma=.99、策略50Hz，未来1秒的奖励折扣到约0.605；同样一次跨级奖励早0.2秒领取，折扣值高约10.57%。奖励最终总进度相同，也仍可能偏好更快到达。本实现还含高度乘子、速度截顶和一次事件奖励，不是简单可假定保留原最优策略的势函数塑形。

实现记录上也有一项需要改进：PT内reward_recipe列的是基础reward字典，新增extra在字典外；只比较PT的权重表会漏掉实际新增目标。PLAN、源码和本次REWARD_AUDIT把它完整记录下来；本轮未修改生产保存逻辑。

## 4. 排除时序、读数、指令和求解器解释

- 0ms和5ms固定物理延迟下，父模型2.2指令稳态分别2.5557123/2.5557124，10m分别2.9055438/2.9056638；移除这档延迟没有消除差异。所有物理时序均2.5/10/20ms；5ms指动作/传感器延迟。
- 原快筛6秒，现补到12秒、取末4秒，仍有相同稳定偏差，不是只截到加速瞬态。
- 训练速度定义为body_vx×cos(pitch)，回放显示航向水平速度。10m两者约2.8930/2.9057，差0.0127；无法解释父到子的约0.3500增量。
- 实际根部位移速度与轮滚动速度一致，非仅用轮编码器将空转当车速。93次无重置、闭链最大0.100858mm，未见求解器爆炸或摔倒/重置污染。
- 实际actor输入命令被捕获，指令范围与源码当前均2.2；旧基类的2.7默认值被当前类覆盖，未发现这组固定回放混入2.7。
- 模型身份、35/78/6、动作顺序、原PPO恢复及-1.5系数对应原父/first/5m/10m，未换模型或模型归一化器。

## 5. 新奖励前就有偏差，历史不是严格“越训越快”

同一0.28m站姿、2.2指令：

| 历史点 | 实际m/s |
|---|---:|
| roughv0_100m | 2.337293 |
| roughv1_060m | 2.598802 |
| roughv1_080m | 2.474334 |
| roughv1_095m | 2.509872 |
| roughv1_100m | 2.527179 |
| roughv1_105m | 2.481553 |
| roughv1_110m | 2.509424 |
| roughv1_115m | 2.501988 |
| roughv1_120m | 2.555713 |

此前Rough-v1在60/80/95/100/105/110/115/120m已有约2.47～2.60m/s超速，存在上下波动。最近新试验的parent→first→5m→10m才呈清楚上升。不能据新增前就存在的偏差，反推出新增奖励是全部原因；也没有证据宣称-1.5本身必然失效或只能从零重训。

还要区分跨引擎结论：训练在PhysX/fullDR，本次有完整控制通道证据的是MuJoCo名义平地。同一个MuJoCo环境中更换权重即可复现差异，因而不能只归为回放参数切换；但原生PhysX平地是否也同幅度超速仍没有数据，腿控变化的影响可能被sim2sim差异放大。该限制不影响本机条件下的腿/轮互换结果。

## 6. 下一步最小修复方向（尚未执行）

第一项应纠正这次进展奖励的范围：台阶前物理平地沿用原速度目标，额外奖励只服务真正跨级与合适姿态，不再给无障碍助跑持续发向前进度分。保留−1.5e²和原指数项，从原7cc1父模型做单因素同预算对照；当前高站姿采样仍可保留，以判断分布改变和dense奖励各自作用。

若去掉助跑进展后低站姿仍回退，才考虑对普通平地、低站姿的腿部输出加入旧策略保留约束，或重新平衡该条件的采样。不要只全局加强速度罚：它会同时压高站姿/越障瞬态，而本次直接定位的是共享腿控的状态迁移。没有建议冻结整条腿控或另改观测接口；确切修复参数要由该对照结果决定。

本机控制原因证据充分；目标机SSH仍超时，尚无这次原生PhysX同条件fullDR结果，也没有奖励训练消融，所以不把本机93例推广成实车/fullDR定论。不启动任何新训练、不替换原最佳模型。
