## Replay and fullsave limitations

Installed85M2 explicitly declares replay_not_saved_matching_upstream_resume_not_exact_PhysX_replay=True. Its _checkpoint stores WM/Pi/critic, all three optimizers, iteration/wall/sim/config; the publisher also stores native observation history and bridge ep_step. Replay storage/ptr/size, loop-local fractional step_accumulator and interval stats are not saved. There is no legitimate way to recover missing replay from that checkpoint or infer it from a raw prefix without another authorized data transformation. This candidate therefore uses fresh replay refill on85->86 and reports replay_restored=false.

The unwired schema mod4.supermimic.continuation_state.v1 snapshots exact ring storage/T/N/ptr/size, old observation history/ep_step, cumulative counters, RNG state and ownership policy for possible future complete saves. It is NOT inserted into this bridge's publisher and does NOT change the installed85 NATIVE_CONTRACT. A future replay-enabled publisher must declare a new truthful contract, augment and verify its fresh stage before publication, verify ring shape/dtype/ptr/size and source/reference/runtime identity, and include the extension in full CPU review. Only then can replay restore be enabled.

If retained replay is later appended after a physical new-episode reset, its newest old nonterminal transition and the first fresh transition must not form a fictitious WM trajectory. The proposed pure mask multiplies the original done mask by ep_step continuity without rewriting real done flags or sampling distributions. source sample_starts already pads by ep_step and oldest available age. The new mask is tested but not installed or wired; next actual replay sampling/source admission remains pending.

Production replay64x20000 with the existing fields occupies1,081,600,000 bytes (845 bytes per transition), plus102,400,000 bytes for128x10 observation history. This size is derived from source shapes, not allocated or read from actual replay. CPU copy/staging/fullsave latency and target RAM/disk headroom must be admitted inside the unchanged3600/300 save boundary before enabling that future schema. The current source loop has integer24 collection rows per iteration (utd1/24), so its local fractional accumulator is identically zero at completed iteration boundaries; arbitrary future utd or mid-update exact resume would require explicit phase/accumulator serialization rather than a new exact-resume claim.
