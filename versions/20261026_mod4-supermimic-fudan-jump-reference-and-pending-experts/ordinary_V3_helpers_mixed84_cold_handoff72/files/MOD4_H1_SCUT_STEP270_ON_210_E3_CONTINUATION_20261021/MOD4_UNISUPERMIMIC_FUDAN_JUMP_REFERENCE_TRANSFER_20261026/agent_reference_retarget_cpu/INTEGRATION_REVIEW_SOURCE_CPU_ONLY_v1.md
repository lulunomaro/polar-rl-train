## Source boundary

`supermimic_reference_adapter_v1.py` reads only measured body poses, measured sample time, wheel bottoms, and wheel contact forces from a newly authorized capture. Its NPZ importer materializes five allowlisted members: `time`, `body_position`, `body_quaternion_wxyz`, `wheel_bottom_world_z`, `wheel_normal_contact_N`, plus the pinned MJCF body-name structure and producer receipt. It never materializes foreign joint angles, joint velocities, torques, raw/executed actions, policy observations, or foreign dynamics transitions. The producer receipt must contain the exact local artifact path, producer/two-host verified SHA256, pinned commit `8204e853dfd2ed06d85a322e1a998c3d20a3be2c`, explicit new-capture authorization, and source jump validation status. The importer requires the original capture case to be complete. XML preorder plus world is checked against both pose-array dimensions; includes are rejected until producer body-name metadata is available.

MuJoCo source quaternions are wxyz. Native measured root13 is xyzw and the existing bridge already packs it to wxyz. This adapter does not change that bridge conversion and does not claim a new SDK quaternion bug.

`reference_schema_v1.json` defines canonical measured task-space demonstrations and exported own-robot native references. Strict increasing measured sample times, finite values, row shapes, wxyz quaternion norms, binary left/right contacts, and reference provenance are checked by the Python loader. The original XML actual timestep and script-declared timestep remain separate. Resampling uses measured times, linear pose-position interpolation, quaternion SLERP, and contact zero-order hold. There is no assumed equivalence between 2 ms actual XML physics and a declared 5 ms script clock.

## Retarget method and pending feasibility

Root/chassis displacement is expressed in the source initial heading frame, normalized by source root-to-wheel rest geometry, scaled to the own robot's rest geometry, and rotated into the requested own heading. Limb target geometry uses deviations of each wheel center in the source chassis frame from its baseline; those deviations are scaled and added to own rest wheel geometry. This transfers compression/extension and relative chassis/wheel paths. It does not copy foreign q, joint limits, actions, torques, or dynamics. A standing jump retains zero demonstrated forward displacement. There is no invented 270 mm rise or invented successful step crossing.

`own_usd_closed_chain_ik_v1.py` derives 30 joint names and frames from the actual own USD in actual geometry body order. It solves 16 own leg coordinates with deterministic bounded damped least squares, using all 6 authored spherical loop closures, own USD joint limits, the existing input-difference window, and the four own transmission constraints. The current asset's drive links physically remain parallel to their source links: gearing -1 is checked against actual USD metadata, then geometric body parallelism is checked before equal joint coordinates are used. The incorrect `q_drive = -q_reference` interpretation is rejected by the CPU contract.

Every exported frame must fit its wheel targets within the stated 1 mm approximation tolerance and retain the existing 2 mm closed-chain protection. These are reference fit checks, not additional uniform physical health or graduation thresholds, and do not change the existing per-environment reset or batch behavior. Existing native/160k-query numerical evidence is reused; no new FP64/bitwise/triangle audit is introduced. Unreachable/nonconverged frames retain an explicit pending status; the exporter refuses to fabricate a complete native reference.

The two main wheel phases are derived from the **own** center path and own collision radius with an explicit rolling assumption in measured support, held in flight. The eight guide-roller spins are held at the own seed. Those unidentifiable q/dq channels are masked from conditioning and imitation. Source contact phases are retained as reference metadata and used for rolling construction; they are not applied actions or physical phase/gate choices. Motor torque-speed feasibility, collision nonpenetration, and own plant task success remain pending. Static IK is not a dynamics certificate.
